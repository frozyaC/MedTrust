# Web-search fallback через SearXNG

MedTrust использует локальный экземпляр SearXNG как web-search provider. SearXNG предоставляет HTTP API, в котором можно запросить результаты в формате JSON через `GET /search?q=...&format=json`; формат `json` должен быть включён в `search.formats` в `settings.yml`.

## Архитектура

```text
POST /api/v1/query
        |
        v
   scope validation
        |
        v
 Wiki.js hybrid retrieval
        |
        +---- достаточно релевантно ----> GigaChat
        |
        +---- недостаточно ------------> SearXNG
                                          |
                                          v
                              HTTPS + domain allowlist
                                          |
                                          v
                               query-topic relevance gate
                                          |
                                     WEB1 / WEB2 / WEB3
                                          |
                                          v
                                       GigaChat
```

SearXNG запускается локально в Docker. Официальная документация поддерживает container/Compose-развёртывание и конфигурацию через `/etc/searxng/settings.yml`.

## Конфигурация

В `.env` достаточно указать:

```env
WEB_SEARCH_ENABLED=true
SEARXNG_URL=http://127.0.0.1:8080
WEB_SEARCH_TIMEOUT_SECONDS=15
WEB_SEARCH_FALLBACK_TIMEOUT_SECONDS=8
WEB_SEARCH_LANGUAGE=ru
WEB_FALLBACK_MAX_DOMAINS=4
WEB_FALLBACK_DOMAINS=nice.org.uk,pubmed.ncbi.nlm.nih.gov,cr.minzdrav.gov.ru,who.int
WEB_SOURCE_MAX_CHARS=6000
WEB_MIN_WIKI_DENSE_SIMILARITY=0.62
```

API key для MedTrust не нужен.

## Запуск

```powershell
docker compose up -d db searxng
```

Проверка UI:

```text
http://127.0.0.1:8080
```

Проверка JSON API:

```powershell
Invoke-RestMethod "http://127.0.0.1:8080/search?q=мигрень&format=json"
```

## Безопасность web-источников

Внешний ответ сначала проходит allowlist:

1. Сначала проверяется обычный поиск.
2. URL должен использовать `https`.
3. Домен должен точно совпадать с `WEB_SAFE_DOMAINS` или быть его поддоменом.
4. Парсер забирает расширенный пул поисковых кандидатов (до 15–30 в зависимости от лимита), а не обрезает результаты до финальных 3 источников. Для доменного fallback по распознанным медицинским темам используется короткая англоязычная формулировка темы и типа запроса, что помогает искать русскоязычные запросы в англоязычных каталогах NICE/PubMed.
5. Перед загрузкой страницы отбрасываются только явные противоречия: например, запрос о мигрени не должен загружать документ, явно посвящённый ME/CFS. Если заголовок или сниппет неоднозначен и не подтверждает тему, это считается недостатком метаданных, а не доказательством нерелевантности.
6. Безопасные неоднозначные кандидаты ограниченно обогащаются текстом HTML-страницы размером до `WEB_SOURCE_MAX_CHARS`; только после этого применяется строгая финальная проверка темы и типа запроса. Если страница недоступна, проверяется исходный сниппет. HTTP-редиректы не следуются.
7. Если NICE возвращает только обзорную страницу `/guidance/<id>`, а запрос требует диагностики, лечения, симптомов или рекомендаций, поиск переключается на `/guidance/<id>/chapter/recommendations`. Для этого раздела минимальный лимит извлечённого основного текста — 14 000 символов даже при старом `WEB_SOURCE_MAX_CHARS=6000` в `.env`; HTML-парсер предпочитает `main`/`article`/`main-content` и исключает навигацию и футер. Итоговый фрагмент ограничивается тем же лимитом, чтобы не передавать бесконтрольно длинные страницы в контекст.
7. В prompt включаются только прошедшие тематическую проверку результаты; каждый источник маркируется `[WEB1]`, `[WEB2]`, `[WEB3]`.
8. `RagService` повторно проверяет результаты перед добавлением в prompt и `sources`, поэтому нерелевантный источник не пройдёт даже при замене search-provider.
9. Web-контент считается недоверенным: GigaChat получает явную инструкцию игнорировать любые инструкции внутри найденных страниц. Structured `patient` context не отправляется в SearXNG.

Allowlist находится в `.env` и позволяет ограничить ответы медицинскими источниками.

## Доменный fallback

Например, для запроса о диагностике мигрени backend может дополнительно отправить в SearXNG запросы вида:

```text
site:nice.org.uk migraine diagnosis guidelines adults
site:pubmed.ncbi.nlm.nih.gov migraine diagnosis guidelines adults
site:cr.minzdrav.gov.ru Какие современные рекомендации по диагностике мигрени у взрослых?
site:who.int migraine diagnosis guidelines adults
```

Англоязычная тематическая формулировка улучшает recall на англоязычных медицинских сайтах даже когда исходный вопрос задан по-русски. Расширенный пул не означает ослабления качества: итоговые источники проходят проверку полного текста и типа запрашиваемой информации, а затем ещё раз валидируются в RAG. Все страницы также проходят HTTPS + allowlist фильтр.

## Статусы

`SearXNGWebSearchClient` возвращает:

- `not_attempted` — поиск не запускался;
- `success` — найдены и прошли allowlist результаты;
- `disabled` — web-search выключен;
- `no_provider_results` — SearXNG не вернул результатов;
- `no_safe_results` — SearXNG вернул результаты, но ни один не прошёл HTTPS + domain allowlist;
- `no_relevant_results` — безопасные страницы нашлись, но не соответствуют теме запроса;
- `api_error` — ошибка HTTP/сети;
- `invalid_response` — ответ не удалось разобрать как JSON.

Если Wiki.js недостаточно релевантен и ни обычный, ни доменный SearXNG-поиск не дают безопасных тематически релевантных результатов, неподходящие страницы исключаются. Генерация ответа продолжается без этих страниц: модель может дать справочный ответ из общих знаний и должна отметить отсутствие подтверждения в найденных материалах MedTrust.

## Answerability и prompt

Порог similarity не служит запретом на использование Wiki-контекста: если сильных совпадений нет, лучшие найденные Wiki-фрагменты всё равно передаются в prompt, а SearXNG запускается как дополнительный поиск. GigaChat получает доступные релевантные источники и при отсутствии источников всё равно формирует ответ из общих знаний, обозначая пробел в базе MedTrust.

## Контроль целостности цитат

Нерелевантные web-результаты, не прошедшие allowlist или проверки содержания, не передаются в prompt. Цитаты в ответе сопоставляются с кандидатами только для диагностики; отсутствие либо неизвестная цитата не блокирует ответ. Массив `sources` содержит переданные модели источники с флагом `used_in_answer`.


## Проверка достаточности веб-доказательств (v21)

После загрузки безопасной страницы результат должен пройти две проверки: `is_relevant_web_result` проверяет тему и тип запрашиваемой информации; `has_answerable_web_evidence` проверяет, что сама страница/сниппет, а не только заголовок или URL, содержит содержательный текст по этой теме. Если нет подходящих и информативных источников, RAG всё равно запускает генерацию. Постгенерационной проверки, способной заменить ответ, нет; найденные источники и citation markers используются только для отладки. Это уменьшает ложные отказы, но не гарантирует медицинскую корректность ответа.
