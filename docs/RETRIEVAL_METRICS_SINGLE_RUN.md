# Retrieval metrics для одного LangSmith Run

Этот инструмент не меняет runtime MedTrust. Он постфактум рассчитывает document-level метрики по privacy-safe `retrieved_chunks` корневой трассировки и прикрепляет численные оценки к этой трассировке через LangSmith Feedback.

## Подготовка

В `tests/evaluation/retrieval_demo_labels.json` находится ручная эталонная разметка для демонстрационного сценария травмы около пяти дней назад. Для него релевантны документы:

- `Регистратура/Словарь/Травматология/Общая_информация`
- `Регистратура/Словарь/Травмпункт/Травмпункт`

Это ручная разметка одного демонстрационного кейса, а не статистическая оценка всего корпуса. Перед публикацией убедитесь, что выбранная трассировка относится к этому сценарию.

## Запуск

1. В LangSmith откройте нужную трассировку и скопируйте ID именно корневого Run `MedTrust RAG query`, не дочернего `MedTrust hybrid retrieval`.
2. Из корня локального репозитория сначала выполните безопасный просмотр без отправки feedback:

   ```powershell
   python scripts/publish_retrieval_metrics.py --run-id <ROOT_RUN_ID> --k 5 --dry-run
   ```

3. Убедитесь, что в выводе указаны нужный Run и два эталонных пути. Затем отправьте метрики:

   ```powershell
   python scripts/publish_retrieval_metrics.py --run-id <ROOT_RUN_ID> --k 5
   ```

Скрипт создаёт четыре numeric feedback-оценки в LangSmith: `retrieval_precision_at_k`, `retrieval_recall_at_k`, `retrieval_mrr_at_k`, `retrieval_ndcg_at_k`. Дополнительные поля feedback содержат K, ID разметки, число уникальных документов и эталонные пути.

## Методика

Оценочная единица — уникальный путь Wiki-документа. Повторные чанки из одного документа схлопываются, чтобы один документ не увеличивал Precision/Recall только за счёт большого числа фрагментов. Для Precision@K используется фиксированный знаменатель K; Recall@K делится на число эталонно релевантных документов; MRR@K учитывает позицию первого релевантного документа; nDCG@K оценивает порядок релевантных документов при бинарной релевантности.

Для приведённого демонстрационного retrieval (порядок уникальных путей: нерелевантный скрипт, затем два релевантных документа) ожидаемый результат при K=5: Precision@5=0.4, Recall@5=1.0, MRR@5=0.5, nDCG@5=0.6934. Значения иллюстрируют только этот размеченный запрос и не должны интерпретироваться как среднее качество системы.

Тексты запроса, ответа и чанков инструмент не читает и не отправляет. Используются только ID Run, пути документов и численные метрики.
