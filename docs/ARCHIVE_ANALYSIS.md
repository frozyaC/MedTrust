# Анализ предоставленного архива `Суфлёр.zip`

В архиве **26 Markdown-файлов**. Важно: физическое имя файла не является главным идентификатором Wiki.js-страницы. Каноническая логическая локация документа задаётся полем:

```text
Путь: Регистратура/Словарь/Лаборатория/Анализы_крови/ОАК
```

Поэтому backend использует `Путь:` как `source_key` документа и восстанавливает иерархию:

```text
Регистратура
└── Словарь
    └── Лаборатория
        └── Анализы крови
            └── ОАК
```

## Верхние ветки

В выгрузке присутствуют три класса знаний:

- `Регистратура/Словарь` — 18 документов;
- `Регистратура/Скрипты` — 5 документов;
- `Регистратура/Обзвон` — 3 документа.

Это означает, что вопрос вроде «как отвечать пациенту на возражение» и вопрос «куда записать пациента с травмой» должны попадать не только в разные текстовые chunks, но и в разные ветки knowledge tree.

## Примеры

```text
Регистратура/Словарь/Травматология/Общая_информация
Регистратура/Словарь/Травмпункт/Травмпункт
Регистратура/Словарь/Укус_клеща
Регистратура/Словарь/Лаборатория/Анализы_крови/ОАК
Регистратура/Скрипты/Чат
Регистратура/Скрипты/Возражения
Регистратура/Обзвон/Общие_правила
```

## Архитектурное следствие

Для MedTrust путь нужно трактовать как **смысловой классификатор документа**.

Поэтому в реализации он используется четырьмя способами:

1. **Embedding context** — путь добавляется перед текстом chunk.
2. **Weighted lexical search** — путь имеет более высокий вес, чем основной текст.
3. **Отдельный `path_vector`** — можно независимо определить, совпала ли ветка Wiki.js с запросом.
4. **Citation** — path возвращается frontend, чтобы регистратор видел источник и мог открыть/найти статью.

Таким образом, если в двух статьях встречается одинаковый термин, но одна находится в `Словарь/Лаборатория`, а вторая — в `Скрипты`, path retrieval помогает различать их по назначению.

## Почему не следует извлекать путь только из имени файла

Имена файлов в архиве могут быть длинными, сокращёнными или не совпадать с логическим названием страницы. В некоторых документах `# H1` отсутствует, но `Путь:` всегда предоставляет структурный идентификатор. Поэтому `source_key = wiki_path`, а filename используется только как вспомогательная metadata.

## Что делать при реальном подключении к Wiki.js

Для production ingestion не нужно сохранять физическую структуру локальной папки. Нужно забирать у Wiki.js как минимум:

- `path`;
- `title`;
- `content`;
- `updatedAt`;
- идентификатор страницы;
- URL страницы.

Локальный ingestion из ZIP оставлен как MVP, потому что он воспроизводимо работает на предоставленной выгрузке и позволяет разработчикам независимо протестировать retrieval до подключения к API Wiki.js.
