# Почему `Путь:` — часть retrieval semantics

Для выгрузки MedTrust логическая структура Wiki.js задаётся внутри каждого Markdown-файла строкой `Путь:`. В предоставленном архиве 26 документов имеют разные ветви:

- `Регистратура/Словарь/...`
- `Регистратура/Скрипты/...`
- `Регистратура/Обзвон/...`

Например:

`Регистратура/Словарь/Лаборатория/Анализы_крови/ОАК`

и

`Регистратура/Скрипты/Чат`

не являются просто двумя URL. Они сообщают, **к какому типу знаний относится документ**.

## Как путь используется

### 1. Embedding context

Перед векторизацией chunk превращается в:

```text
Путь: Регистратура > Словарь > Лаборатория > Анализы крови > ОАК
Название: Общий анализ крови
Раздел: ...
Содержание:
...
```

Так embedding видит и текст, и место документа в дереве знаний.

### 2. Lexical retrieval

PostgreSQL FTS имеет повышенный вес для title/path/section и меньший для content.

### 3. Отдельный path retrieval

Создаётся отдельный `path_vector`. Если пользователь спрашивает, например, про «лабораторию», «скрипт», «обзвон» или конкретную ветку, система получает отдельный retrieval signal.

### 4. Weighted RRF

Итоговая формула:

`score = Wd/(60 + dense_rank) + Wl/(60 + lexical_rank) + Wp/(60 + path_rank)`

Для MVP `Wp = 1.25`, остальные веса равны `1.0`.

Преимущество этого подхода: путь нельзя «потерять» из-за того, что в содержимом нескольких статей встречается похожая медицинская терминология.

## Почему не отправлять весь путь только в metadata

Metadata полезна для фильтрации и цитирования, но недостаточна как единственный retrieval mechanism. В MedTrust путь сам несёт классификационную семантику, поэтому он должен участвовать и в embedding text, и в lexical retrieval.
